# リリースノート v0.2.0

## 概要

画面から操作できる **Electron UI** と、uv や Python が無い Mac でも動く**配布版（署名・公証済みの .app）**を
追加しました。あわせて、保存フォルダの**レイアウトを年月フォルダ振り分けに変更**し、**正本 DB を保存フォルダの
外（データフォルダ）に 1 つだけ置く**構成へ移しました。1 つの正本 DB で複数の保存フォルダを管理します。

保存フォルダの識別、detector 自身のデータの扱い、読めない場合の扱いなどの安全面も強化しています。
これらは PR #3 のコードレビュー（Codex / Claude）で見つかった点で、すべて対応済みです（最終レビューで指摘 0 件）。

設計書: `__documents/設計書_v020_重複判定アーカイバ.md`（v0.1.0 の設計書は凍結）

## 変更内容

### 新機能

#### Electron UI（electron-ui/）

detector の 4 サブコマンド（`add` / `verify` / `delete-duplicates` / `report`）を画面から実行できます
（登録済みの保存フォルダの一覧 `archives` は CLI だけ）。
UI はフォームの値から CLI の引数を組み立てて detector を子プロセスとして起動し、出力を表示するだけです。
**ロジックは持ちません**（境界は CLI に固定。設計書 §16）。

- ドラッグ＆ドロップ、保存フォルダの履歴、前回入力の復元（`--yes` は復元しない）
- 実行するコマンドを常に表示し、コピーできる。引数の組み立ては `commands.js` の 1 か所だけなので、表示と実行内容は食い違わない
- 進捗を判定結果ごとの件数で表示し、中断にも対応する（プロセスグループへ SIGINT を送り、detector は `interrupted` で後片付けする）
- `--yes`（実際に削除する）の確認ダイアログはメインプロセスで出す。画面側の実装ミスで確認を飛ばせない
- 実行後に CSV を Finder で開く導線、ログの場所を開く導線
- **6 言語に対応**（日本語・英語・フランス語・ドイツ語・イタリア語・エストニア語）。言語は「前回選んだ言語 → OS の言語 → 英語」の順で決め、画面右上で切り替えられる
- 詳細設定でデータの保存場所を表示し、「Finder で表示」で開ける
- パス欄には、ターミナルからコピーした形（引用符・`\ ` のエスケープ・`~/`）をそのまま貼れる。**Windows のドライブ指定・UNC パスの `\` は消さない**

#### 配布版（.app）（packaging/）

- `packaging/build_mac.sh` で、PyInstaller で固めた detector と crawler を同梱した `.app` を作る。Developer ID 署名・Hardened Runtime・公証・staple まで行う（Apple Silicon 用）
- **uv・Python・akasyx_crawler のリポジトリが無い環境でも動く**
- データフォルダは `~/Library/Application Support/akasyx-duplicate-detector/`（Windows は `%LOCALAPPDATA%\akasyx-duplicate-detector\`）。UI の設定と Electron のキャッシュも、このフォルダの `ui/` に置く。アプリを完全に消すときは、このフォルダ 1 つを消せば済む
- 配布物には `README.dist.txt`（データの場所・バックアップ・完全削除の手順）と `THIRD_PARTY_LICENSES.txt` を同梱する
- 開発時（`uv run`）のデータフォルダは、これまでどおり `<リポジトリ>/dist/`

#### 保存先レイアウト: 年月フォルダ振り分け（mover.py）

```
<保存フォルダ>/
├── .akasyx/archive.id                         ← この保存フォルダの識別子（uid 1 行）
└── <YYYY-MM>/<投入元フォルダ名>/<相対パス>/[001/]<ファイル名>
```

- 年月は、ファイルの作成日時を**ローカル時刻**で見て決める。作成日時は crawler の `created_at` → 実体の birthtime → 更新日時の順に取り、どれも取れなければ `unknown-date/` に入れる
- 1 フォルダの上限（既定 500 件、`--folder-limit N` で変更）を超えたら、`001/`、`002/` … の枝に分ける
- 投入元が単一ファイルのときは、投入元フォルダ名を付けずに `YYYY-MM/<ファイル名>` に置く
- `--dest-subdir` で投入元フォルダ名の部分を変えられる（`''` を指定すると付けない）

#### 正本 DB の一本化と複数の保存フォルダ（archives.py）

- 正本 DB は保存フォルダの外、**データフォルダの `archive.db` に 1 つだけ**置く（`--archive-db` で変更できる）。保存フォルダを SMB などのネットワーク上に置いても、SQLite はローカルにしか置かれない
- 保存フォルダは `ar_archives` に 1 行ずつ登録し、保存フォルダの中の `.akasyx/archive.id`（uid）と結び付ける。フォルダを移動・改名しても、uid が同じなら同じ登録として扱い、記録上のパスを自動で更新する
- `archives` サブコマンドで、登録済みの保存フォルダの一覧（保存件数・合計サイズ・最後に使った日時）を表示する
- **v0.1.x の保存フォルダを開くと、中の `.akasyx/archive.db` を自動で正本 DB へ取り込む**。旧 DB は削除せず、`archive.db.migrated-<日時>` に改名して残す
  - 取り込む前に WAL を本体へ書き戻すので、WAL にだけあった変更も取り込まれる
  - 「取り込み済み」を取り込みと同じトランザクションで記録する。改名に失敗しても、次回は取り込み直さずに改名だけをやり直す
- 重複判定は**保存フォルダ単位**で行う。別の保存フォルダにある同じ内容は重複扱いにならない（全保存フォルダ共通にする変更を #6 で予定）

#### 投入元の中にある detector 自身のデータは取り込まない（ingest.py）

ホームフォルダを投入元にすると、データフォルダ（処理中の正本 DB や UI の設定）も投入元に含まれます。
これを保存フォルダへ移すと履歴や設定を失うため、取り込みの対象から外します。

| 条件 | 判定 | 実体 |
|------|------|------|
| detector 自身のデータ（データフォルダ全体・正本 DB と -wal/-shm・作業用 DB・ログ） | `skipped_own_data`（**新しい結果値**） | 投入元に残す |

- 除外した件数はサマリ（`own data skipped: N`）・CSV・`ar_ingest_items` に残す。黙って件数を減らさない
- シンボリックリンク経由・大文字小文字違いの表記・`--follow-symlinks` の場合も除外する
- `--prune-empty-dirs`（add / delete-duplicates）でも、自データのフォルダの中の空フォルダは消さない

### 変更（互換性に影響するもの）

- **保存先レイアウトを変更**。v0.1 の「投入元の相対パスをそのまま再現」（mirror）は廃止し、年月フォルダ振り分けだけになった。既存のファイルは移動しない（再配置は将来の拡張）
- **正本 DB の場所を変更**（保存フォルダの中 → データフォルダ）。v0.1.x の DB は、保存フォルダを開いたときに自動で取り込む
- **利用者向けの出力を英語に統一**。サマリは `[Summary] moved: … / duplicates (left in place): … / empty files: … / no hash: … / failed: …`、エラーは `Error: …`、CSV のヘッダは `File name, Source path, Result, Size, Destination, Note`。UI が読むのは `Progress: <n> files (<result>)` と `CSV report: <path>` の 2 行。日本語の出力を読んでいる後段の処理があれば、追従が必要
- 相対パスの `--db-dir` / `--log-dir` は、起動時の作業フォルダを基準に絶対パスにする（crawler と同じ場所を見るため）

### 安全性の強化（事前チェックで断るもの。終了コード 3）

| 条件 | 扱い |
|------|------|
| 保存フォルダがデータフォルダと重なる（含む・中にある・同じ）。例: ホームフォルダを保存フォルダにする | 拒否。データフォルダはオプションで移せないので、保存フォルダの選び直しを案内する |
| 正本 DB・作業用 DB・ログの置き場が保存フォルダの中 | 拒否。`--archive-db` / `--db-dir` / `--log-dir` で外へ移すよう案内する。**フォルダ作成やログファイルの初期化より前に判定する**ので、断るときに保存フォルダの中へ何も書き込まない |
| `archive.id` の uid が正本 DB に無く、保存フォルダに中身がある（別の正本 DB で使っていた等） | 全コマンドで拒否。空の登録として扱うと、既にある内容と同じファイルまで取り込んで重複を作るため。中身が空なら新規登録して続ける |
| 同じ uid の元の保存フォルダが、登録上の場所に残っている（保存フォルダの複製） | 拒否。コピー側の `archive.id` を消すよう案内する。元の場所に無ければ移動として扱う |
| `archive.id` や保存フォルダの配下が読めない（権限・I/O エラー・文字化け） | 拒否。「無い」「空」とはみなさない |

- `archive.id` の無い保存フォルダは、場所から登録を探す。照合は実体（st_dev / st_ino）で行うので、シンボリックリンク経由や大文字小文字違いの表記でも同じ登録を使う。大文字小文字を区別するボリューム上の別々のフォルダは、1 つにまとめない
- `report --ingest-id` は、今開いている保存フォルダの実行履歴だけを表示する

## テスト

- pytest: 163 passed / 4 skipped（CI・ubuntu）。skip の 4 件は、ボリュームが大文字小文字を区別するかや、権限の有無で実行できる環境が限られるもの
- `node --test`（electron-ui）: 10 passed。辞書が JSON として読めること、6 言語のキーと差し込み名が揃っていること、Windows パスの扱いを検証する
- PR #3 では、push の前にローカルで自己レビュー（`/code-review`）を通してから出す進め方に切り替えた。最終コミット `4f82d64` の claude-review-server のレビューは、Critical / High / Medium / Low すべて 0 件

重点的に検証した箇所:

- 年月の決め方（作成日時がローカル時刻で月をまたぐ場合、birthtime の無い Linux では更新日時で決まる場合）
- 投入元の中の自データを取り込まず、空フォルダの削除でも消さないこと（add / delete-duplicates）
- 保存フォルダの識別（移動・複製・別表記・uid 不明・読めない場合）
- v0.1.x の DB の取り込み（WAL にだけある変更、改名に失敗したあとの再実行）
- 拒否するときに保存フォルダの中へ何も書き込まないこと

## 申し送り事項

- **配布版は Apple Silicon の macOS 用だけ**。Windows 版は、PowerShell 版のビルドスクリプトなどが別途必要
- **公証済みの zip を、別の Mac（quarantine 付き）で初めて開く動作は未確認**
- アプリのアイコンは未設定（Electron の既定のアイコン）。appId `net.at-first.akasyx-duplicate-detector` は仮の値
- 今後の課題:
  - #4 `archive.id` の無い既存フォルダを保存フォルダにすると、重複が入る
  - #5 正本 DB を失うと、中身のある保存フォルダを開けない（実物のハッシュから登録し直す adopt を提案）
  - #6 重複判定を全保存フォルダ共通にする
  - #7 接続していないネットワークの登録があると、保存フォルダの照合で待たされる
- レビューで「ベースブランチからある挙動」として対象外にした点（未起票）:
  - `--dest-subdir` に `../..` を指定すると、保存フォルダの外を指せる
  - verify で場所が変わったファイルを登録し直すとき、既存の `unregistered` 行とパスの UNIQUE 制約がぶつかる可能性がある
