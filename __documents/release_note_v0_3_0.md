# リリースノート v0.3.0

**リリース日:** 2026-10-03
**タグ:** v0.3.0

---

## 概要

**重複判定を、1 つの正本 DB に登録したすべての保存フォルダで共通にしました**（#6）。どこか 1 つの保存フォルダに同じ内容があれば、
別の保存フォルダへの取り込みでも重複として投入元に残します。消した保存フォルダの記録を判定から外す `archives --forget` と、
中身のある既存フォルダや正本 DB を失った保存フォルダを実物から登録し直す **`adopt`** を追加しました（#4 / #5）。
どちらも **UI から実行できます**（#11）。

あわせて、止まっている NAS の登録で照合が待たされる問題を解消し（#7）、v0.1.x の DB の取り込みを速くしました（#8）。

設計書: `__documents/設計書_v020_重複判定アーカイバ.md`（v0.3.0 の変更もこの設計書に追記している）

## 変更内容

### 新機能

#### 重複判定を全保存フォルダ共通に（#6・PR #12）

- `add` は、正本 DB に登録されたどの保存フォルダに同じ内容があっても `duplicate` として投入元に残す。
  CSV の備考に「どの保存フォルダのどこにあるか」を出す
- **同じ内容の保存記録（stored）は全保存フォルダで 1 つ**を守る。`add` 以外で記録を stored にする経路（中断の復旧・verify の missing 復活・
  forget の取り消し・v0.1.x の DB の取り込み）も、すべて同じ規則（別の保存フォルダに stored があれば stored にしない）を通る
- `delete-duplicates` は、実物がある保存フォルダ（別の保存フォルダでもよい）で 2 点検証してから消す。新しい判定:

  | 判定 | 意味 | 実体 |
  |------|------|------|
  | `archive_unavailable` | 実物のある保存フォルダに今つながっていない | 消さない（つないで実行し直せば消せる） |
  | `same_file` | 消す対象が保存済みの実物そのもの | 消さない |
  | `source_in_archive` | 投入元のファイルが保存フォルダ（`.akasyx/archive.id` のあるフォルダ）の中にある | 消さない |

- つながっていない保存フォルダにしか無い重複は、取り込みのサマリの後に `Note:` 行（保存フォルダごとの件数と `archives --forget <ID>` の案内）で知らせる
- **`archives --forget <ID>`**: 消した保存フォルダの記録を重複判定から外す（記録は `forgotten` になるだけで、履歴・処置予定フラグは残る）。
  保存フォルダがその場所にあるとき、stored が 1 件も無いときは断る。NAS を外していただけの保存フォルダを外してしまっても、
  次に開いたとき識別子が一致すれば記録が戻る
- 正本 DB を共有する実行は、保存フォルダが違っても 1 本だけにする（**正本 DB 単位の OS のロック**。`archives` 以外の全サブコマンド）

#### adopt — 中身のある保存フォルダを実物から登録する（#4 / #5・PR #13）

- **`adopt <保存フォルダ>`**: 保存フォルダの中のファイルを走査し、実物のハッシュで stored として登録する（ファイルは動かさない）。
  保存フォルダの中の重複は、パス順で最初の 1 つを stored、残りを `unregistered`（`archive_duplicate`）にする
  - `archive.id` の無い既存の写真フォルダなどを、初めて保存フォルダにするとき（#4）
  - 正本 DB を失い、識別子だけ残った保存フォルダを開き直すとき（#5。識別子を引き継ぐ）
- **全部か無しか**: 読めないフォルダ・ハッシュを取れないファイルが 1 つでもあれば、1 件も登録せずに断る
- 中身があるのに記録の無いフォルダは、`adopt` 以外のコマンドで断る（そのまま使うと、中にある内容と同じファイルを重複して取り込むため）。
  `adopt` が途中で落ちたときは「adopt 待ち」の印が残り、`adopt` をやり直すまで他のコマンドで断る
- 新しい結果値 `adopted`。戻るのは実物の登録と識別子だけで、取り込み履歴・元のパス・処置予定フラグは戻らない

#### UI から登録の管理（#11・PR #14）

- **「保存フォルダ一覧」タブ**: 登録済みの保存フォルダを一覧で表示し（場所にあるか・保存件数・外した記録・adopt 待ち・最終使用日時）、
  行ごとに**「登録を外す」**。確認ダイアログはメインプロセスで必ず出す。外すときは一覧を読んだ正本 DB と識別子（uid）を使うので、
  あとで正本 DB の指定を変えても別の保存フォルダを外さない
- **「既存ファイルの登録」タブ**: `adopt` を実行する
- 取り込みの結果に `Note:` 行が出たら「保存フォルダ一覧を開く」、adopt を求めて断られたら「ファイルを登録する」の導線を出す
  （別の正本 DB で使っていた可能性のあるフォルダの断りでは、adopt を勧めない）
- CLI に UI 用の `archives --json`（一覧を JSON で出す）と `archives --forget <ID> --expect-uid <UID>`（uid が違えば断る）を追加
- 6 言語の辞書を更新

### 改善

- **止まっている NAS の登録で待たされない**（#7・PR #17）
  - 識別子の無いフォルダを開くとき、大文字小文字と Unicode の正規化（NFC / NFD）を除いて表記が同じ登録だけを照合する。表記の違う登録には I/O をかけない
  - 移動した保存フォルダの元の場所の確認は 10 秒で打ち切り、警告を出して移動として扱う（OS のタイムアウトを待った後と同じ結果で、速くなるだけ）
- **v0.1.x の DB の取り込みを速く**（#8・PR #16）: stored の判定を行ごとから 1 回の問い合わせにまとめた（stored 20,000 件で 3.96 秒 → 1.53 秒。結果は同じ）
- delete-duplicates の重複していた処理を 1 か所にまとめた（#9 / #10・PR #15。動作は変えない）
- 配布用 zip から `._`（AppleDouble）を除き、混入したらビルドを止める（別の Mac で Finder 展開すると「壊れている」と拒否されていたため）。配布物の著作権表記を個人名にした
- リリースノートを手書き優先にした（`__documents/release_note_vX_Y_Z.md` があればそれを Release の本文にする）
- 確認用の起動スクリプト `_bash/start_ui.sh`（開発版の起動。`--app` で配布版の `.app` を開く）

### 変更（互換性に影響するもの）

- **重複判定の範囲が変わる**。v0.2.0 では別の保存フォルダにある同じ内容は重複にならなかったが、v0.3.0 では重複として投入元に残る。
  既存の DB に保存フォルダをまたぐ同じ内容があっても、そのまま動く（行は動かさない）
- **中身があるのに記録の無いフォルダは断る**（`adopt` を案内）。v0.2.0 では空の登録として始まり、中にある内容と同じファイルまで取り込んでいた
- **同じ正本 DB を使う実行は同時に 1 本だけ**。ロックできない場所（ネットワーク FS 等）に正本 DB を置くと断る（正本 DB はローカルディスクに置く）
- **新しく登録する保存フォルダが別の保存フォルダの中にある・中に含むときは断る**（v0.2.0 以前に登録済みの入れ子はそのまま開ける）。
  `add` の投入元が保存フォルダの中にある・中に保存フォルダを含むときも断る
- `archives`（一覧・`--json`・`--forget`）は正本 DB を作らない。無ければ「まだ無い」と出して終わる（`--forget` は断る）
- 以前の版がシンボリックリンク経由で記録した登録は、識別子を失った状態では場所から見つけない（中身があれば adopt を求めて断るので重複は入らない）

### 安全性の強化（事前チェックで断るもの。終了コード 3）

| 条件 | 扱い |
|------|------|
| 中身があるのに記録の無いフォルダ（`archive.id` が無い・識別子が正本 DB に無い） | `adopt` 以外で拒否。識別子があるときは、別の正本 DB（`--archive-db`）の指定を先に案内する |
| adopt が途中で落ちた保存フォルダ（adopt 待ち） | `adopt` 以外で拒否 |
| 消した保存フォルダの跡に、記録の無い中身のあるフォルダが置かれた | `adopt` 以外で拒否 |
| 投入元・取り込み先・`--trash-dir` が別の保存フォルダと重なる | 拒否（走査やハッシュの前、取り込み先を登録する前に断る） |
| 正本 DB を別の実行が使っている／ロックできない場所にある | 拒否 |

## 申し送り事項

- **配布版は Apple Silicon の macOS 用だけ**。Windows 版は未着手（2026-09-26 に必須と決定）。次の経路は Windows で未確認:
  - 正本 DB のロック（`msvcrt.locking`）
  - UI の一覧取得のタイムアウトでプロセスツリーを止める処理（`taskkill /T /F`）
- **本物の止まっている NAS での待ち時間は未確認**（単体テストで stat を遅らせて確認）
- 意図した代償（設計書 v020 §4）:
  - 元の場所が 10 秒以上かかって応答する NAS に元の保存フォルダが残っていると、複製を移動と取り違える（データは失われない。複製を消せば元の方を開ける）
- 今後の課題（未起票）:
  - ファイル ID を返さない FS（一部の SMB）で、親フォルダ名が NFC / NFD（や大文字小文字）だけ違うと、同じ保存フォルダを複製として断る（#1 で「親の表記違いは別々とみなす」と決めた挙動の副作用）
